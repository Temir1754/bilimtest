## 3. Схема таблиц

Всё, что про учеников, — в схеме `school` (№45). Ссылки на вопросы и темы — просто id, без внешних ключей.

| Таблица | Поля | Кто видит |
|---|---|---|
| `public.profiles` (есть) | + `nickname` (уникальный, без учёта регистра), `first_name`, `last_name`, `blocked_at`, `school_id`, `school_other` | свою строку — сам; все строки — админ. Ученики и учителя друг друга не видят |
| `public.teacher_info` (новая) | `user_id`, `subjects uuid[]`, `grades int[]` | сам учитель и админ |
| `public.regions` (новая) | область → город/район (дерево: `parent_id`), названия kk/ru | все |
| `public.schools` (новая) | `region_id`, `name_kk`, `name_ru`, `approved`, `added_by` | одобренные — все; новые, введённые вручную, — админ проверяет |
| `school.students` | `user_id`, `grade`, `class_code` (пока только хранится), `consent_at`, `parent_consent` (галочка 16 лет) | сам ученик и админ; учитель — нет (до этапа 8) |
| `school.test_runs` | как в stage8-schema.md: `student_id`, `subject_id`, `grade`, `topic_id`, `score`, `total`, `finished_at` (+ `topic_title` для старых результатов из браузера) | только сам ученик |
| `public.app_settings` (есть) | + `teacher_drafts_per_day` = 50, `signup_open` (учитель / ученик) | админ |

### Правила (база, RLS) — каждое с тестом

- **Роль ставит триггер** при создании аккаунта: из формы берётся только `student` или `teacher`. Любое другое значение,
  в том числе `admin`, — ошибка регистрации. Менять роль может только админ (функция `set_user_role`, уже есть).
  Колонка `role` закрыта для изменения через API (уже сейчас). Тесты: регистрация с `role=admin` — отказ;
  ученик меняет себе роль запросом — отказ.
- Триггер проверяет и остальное: никнейм, согласия, у ученика класс 4–11; поле-ловушка не пустое — отказ.
- Заблокированный (`blocked_at`): вход запрещён (`banned_until` в Supabase Auth ставит функция админа), а все правила
  `is_staff()` возвращают «нет».
- Учитель: не больше 50 черновиков в сутки по времени Алматы (число в `app_settings`); админ — без лимита.
- Ученик видит только свои `test_runs` и свою строку `students`; данные учителей ему не видны.
- Удаление аккаунта: функция базы удаляет свой аккаунт; результаты и профиль удаляются вместе с ним.

## 4. Защита от ботов

- **Поле-ловушка** в форме (скрытое поле, человек его не видит) — проверяет триггер.
- **Капча Cloudflare Turnstile** — бесплатная, обычно невидимая. Её проверяет сам Supabase при регистрации. Это и есть
  главная защита: запрос в обход формы без капчи не пройдёт.
- **Лимит частоты** регистраций в настройках Supabase Auth (по IP). Внимание: в школе весь класс выходит с одного IP (№21),
  поэтому лимит ставим с запасом (например, 60 регистраций за 5 минут).

## 5. Скорость сайта ученика

Библиотека входа (supabase-js) весит около 50 КБ. На главную страницу её не добавляю: она загружается, только если
пользователь уже вошёл или нажал «Кіру». Тесты без входа работают как сейчас.

## 6. Результаты ученика и перенос из браузера

Сайт ученика пока берёт вопросы из файлов `data/*.json` со **старыми** темами, а в базе вопросы уже разложены по новым
(старые темы удалены). Поэтому:

- результаты тестов в базу правильно записываются только после **этапа 4** (сайт берёт вопросы из базы);
- лучшие результаты из браузера, набранные до этапа 4, относятся к старым темам. Предлагаю перенести их в историю как
  «старые результаты» с названием темы (без привязки к новым темам).

## 7. Порядок работы (подзадачи для ROADMAP)

1. Резервная копия; миграция: profiles + teacher_info + regions/schools + school.students; триггер роли; тесты RLS.
2. Экран `/login`: вход, «Забыли пароль?», переход по роли; шапка с никнеймом и меню.
3. Регистрация учителя; справочник школ; лимит 50 черновиков; кабинет `/teacher`.
4. Админка: экран «Пользователи» (фильтр, поиск, блокировка).
5. Регистрация ученика; кабинет `/me` (настройки, смена пароля, удаление аккаунта).
6. Этап 4 (сайт ученика на базе) — нужен для пункта 7.
7. Результаты ученика в базу, история и лучшие результаты в `/me`, перенос из браузера при первом входе.
8. Политика конфиденциальности (kk/ru/en) — текст проверяет юрист.
