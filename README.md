# Білімтест — бесплатные школьные тесты (4–11 классы)

Сайт тестов по 16 предметам на казахском, русском и английском языках.
Сейчас: 16 предметов, 267 тем, 1336 вопросов.

Проект переводится на Vite + React + TypeScript + Supabase. Сейчас сайт берёт вопросы из папки `data/`;
после подключения Supabase они будут храниться в базе и редактироваться в админке.

## Что где лежит

| Файл / папка | Зачем |
|---|---|
| `src/site/` | Экраны для учеников: главная, предмет, тест, результат |
| `src/lib/` | Логика теста, загрузка данных, хранение результатов |
| `src/i18n/ui.ts` | Тексты интерфейса на трёх языках |
| `src/styles/app.css` | Оформление (перенесено со старого сайта) |
| `data/*.json` | Вопросы, по одному файлу на предмет |
| `tests/` | Автоматические проверки |
| `legacy/` | Старый сайт одним файлом (на память) |

## Как запустить на своём компьютере

Нужен Node.js (уже установлен). Откройте терминал в этой папке и выполните один раз:

```
npm install
```

Запуск сайта для разработки (изменения видны сразу):

```
npm run dev
```

Затем откройте в браузере адрес, который покажет команда (обычно http://localhost:5173). Остановить — `Ctrl+C`.

Другие команды:

| Команда | Что делает |
|---|---|
| `npm test` | Запускает автоматические проверки, включая проверку всех вопросов в `data/` |
| `npm run build` | Собирает готовый сайт в папку `dist/` |
| `npm run preview` | Показывает собранный сайт из `dist/` |

## База данных (Supabase)

Используются два бесплатных проекта Supabase:
- **bilimtest** — основной, с настоящими вопросами;
- **bilimtest-test** — для автоматических проверок; тесты стирают в нём данные.

Ключи хранятся в файле `.env` (образец с подсказками — `.env.example`). Файл `.env` не попадает в git.

| Команда | Что делает |
|---|---|
| `npm run db:push` | Создаёт или обновляет таблицы и правила доступа в основном проекте (файлы `supabase/migrations`) |
| `npm run db:push -- --test` | То же для тестового проекта |
| `npm run import` | Загружает вопросы из `data/*.json` в основной проект и сверяет количество. Повторный запуск не создаёт дублей и не трогает то, что уже есть в базе |
| `npm run import -- --force` | Перезаписывает вопросы в базе содержимым `data/*.json` (правки из админки для этих вопросов пропадут; прежние версии останутся в истории) |
| `npm run make-admin -- you@example.com` | Делает пользователя админом |
| `npm run curriculum -- data/curriculum/grade4.json` | Загружает программу класса: предметы, разделы, темы (вопросы не трогает). `--check` — только проверить файл, `--force` — перезаписать названия из файла |
| `npm run test:db` | Проверяет правила доступа на тестовом проекте |
| `npm run functions` (`-- --test`) | Загружает функции на сервере (`supabase/functions`: создание учителя, сброс пароля, регистрация ученика). Нужен SUPABASE_ACCESS_TOKEN в .env |
| `npx supabase db reset --db-url "TEST_DB_URL" --yes` | Пересоздаёт **тестовую** базу с нуля по всем миграциям (если миграцию исправили после применения). Никогда — с адресом основной базы |

`npm test` тоже проверяет таблицы и правила доступа, но на временной базе внутри компьютера, без интернета.

### Если проект Supabase «уснул»

Бесплатный проект ставится на паузу, если им не пользовались 7 дней. Обычно это тестовый проект.
Признаки: `npm run test:db` или сайт выдают ошибку подключения.

1. Откройте supabase.com и войдите.
2. Выберите проект — на нём будет надпись **Paused**.
3. Нажмите **Restore project** (или **Resume**) и подождите 2–5 минут, пока статус не станет зелёным.
4. Повторите команду.

Данные при паузе не теряются.

## Формат вопросов в data/*.json

**Правильный ответ всегда первым**, сайт сам перемешивает варианты:

```json
[["Вопрос на казахском", "Вопрос на русском", "Question in English"], "правильный", "неверный 1", "неверный 2", "неверный 3"]
```

- Текст, одинаковый на всех языках (числа), пишется одной строкой: `"x² − 9"`.
- Текст на трёх языках — массив из трёх строк: `["қызыл", "красный", "red"]`.
- 3 или 4 варианта ответа.
- Формулы: `\( x^2 \)` внутри строки, `\[ \frac{a}{b} \]` отдельной строкой. Знак `$` для формул не используется.
- Если в тексте вопроса есть перенос строки, всё после него показывается как блок кода.

После правок запустите `npm test`, он найдёт ошибки в файлах.
