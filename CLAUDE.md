# Білімтест — правила работы

## Проект
Бесплатный сайт школьных тестов для 4–11 классов Казахстана на казахском (по умолчанию), русском и английском.
Переводится со статического HTML на платформу с базой, админкой и кабинетом учителя.

- **Стек:** Vite + React 19 + TypeScript, Vitest, Supabase (Postgres, Auth, RLS, Storage, Edge Functions), KaTeX, деплой на Vercel.
- **План:** [docs/ROADMAP.md](docs/ROADMAP.md). **Решения:** [docs/DECISIONS.md](docs/DECISIONS.md). **Журнал по дням:** [docs/sessions/](docs/sessions/README.md).

## Структура
| Путь | Что там |
|---|---|
| `src/site/` | Экраны ученика: App, Home, SubjectView, QuizView, ResultView |
| `src/admin/` | Админка (/admin, отдельный файл сборки): вход, дерево тем, форма вопроса, проверка; свои стили в `admin.css` |
| `src/lib/` | Модель данных (`types.ts`), логика теста (`quiz.ts`), старый формат JSON (`legacy.ts`), источники данных, localStorage |
| `src/components/` | Общие компоненты (Rich — текст с формулами) |
| `src/i18n/ui.ts` | Тексты интерфейса kk/ru/en |
| `src/styles/app.css` | Стили из старого template.html; новое — в конец файла |
| `data/*.json` | Исходные вопросы (формат — в README и `src/lib/legacy.ts`) |
| `data/curriculum/gradeN.json` | Программы классов: предмет → раздел → тема, без вопросов (формат — `scripts/curriculum.ts`) |
| `supabase/migrations/` | SQL-миграции (с этапа 3) |
| `scripts/` | Скрипты, например импорт JSON в Supabase |
| `tests/` | Тесты Vitest |
| `legacy/` | Старый сайт, не менять |

## Команды
- `npm install` — установить зависимости
- `npm run dev` — сайт для разработки (http://localhost:5173)
- `npm test` — тесты без интернета (логика, данные, SQL и RLS на PGlite); `npm run check` — проверка типов
- `npm run test:db` — тесты RLS на тестовом проекте Supabase (TEST_* в .env)
- `npm run db:push [-- --test]` — применить миграции; `npm run import [-- --test] [-- --force]` — импорт data/*.json
- `npm run make-admin -- email` — назначить админа
- `npm run curriculum -- data/curriculum/gradeN.json [--check] [--force] [--test]` — загрузить программу класса (разделы и темы)
- `npm run backup [-- --test]` — резервная копия данных базы в `backups/` (не в git); `npm run restore -- backups/папка --yes [--test]` — вернуть базу к копии
- `npm run move-questions [-- --apply] [--with-none] [--test]` — перенос старых вопросов по таблицам `docs/gradeN-mapping.md` (без --apply — только проверка)
- `npm run build` — сборка в `dist/`; `npm run preview` — посмотреть сборку
- Деплой: описывается на этапе 7

## В начале каждого нового чата
1. Прочитай docs/ROADMAP.md, docs/DECISIONS.md и последний файл из docs/sessions/, выполни `git status` и `git log --oneline -10`.
2. Коротко скажи владельцу на русском: на каком мы этапе, что сделано, что следующее, нужно ли что-то от него.
3. Продолжай работу, не дожидаясь подробного задания.

## Журнал работы (docs/sessions/)
- Один файл на день: `docs/sessions/ГГГГ-ММ-ДД.md`. Разделы: что сделано; принятые решения (номера из DECISIONS.md); проблемы и как решили; коммиты; на чём остановились и что делать в следующий раз; что нужно от владельца.
- В течение дня дописывай в файл сегодняшнего дня то, что сделано. Если файла нет — создай.
- Оглавление `docs/sessions/README.md`: дата, этап, одна строка «что сделано». Новые дни — сверху.
- «Закрой день» или «на сегодня всё»: допиши файл дня, обнови оглавление и блок «Сейчас» в ROADMAP.md, запусти `npm test`, сделай коммит. Потом коротко скажи, с чего начнём в следующий раз.
- Никогда не записывай в журнал пароли, ключи и строки подключения.

## Как работать
- «Продолжай» или «дальше» — бери следующую задачу из ROADMAP.md.
- После каждой законченной задачи: отметь её в ROADMAP.md, обнови блок «Сейчас», сделай коммит с понятным сообщением на русском.
- После каждого этапа: запусти `npm test`, допиши журнал в ROADMAP.md, остановись и объясни, как проверить результат. Жди «дальше».
- Каждое новое решение записывай в DECISIONS.md (дата, решение, причина). Не пересматривай принятые решения без согласия владельца.
- Если видишь решение лучше или что-то неясно — сначала спроси, не угадывай.
- Если задача больше, чем казалось, разбей её на подзадачи в ROADMAP.md.
- Объясняй простым языком на русском: владелец не программист. Команды давай готовыми для копирования.
- Никогда не коммить `.env` и секретные ключи. service_role ключ и ключи ИИ — никогда в браузерном коде.
- Новая таблица в миграции: явно `grant` нужные права, включить RLS, добавить проверки в tests/sql и tests/cloud.
- Пиши код в стиле окружающего: те же имена, плотность комментариев (комментарии на русском).
